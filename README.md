# Бот-анкетница

Telegram-бот для приёма и модерации анкет участников. Python 3.11 + aiogram 3 +
хранение данных в JSON-файлах (без базы данных). Готов к запуску на Railway
через Docker.

## Что умеет бот

- Пошаговый приём анкеты (8 вопросов, кнопки для выбора возраста, до 2 фото скина).
- Отдельная заявка на пост младшего модератора (10 текстовых вопросов) —
  своя тема, свой набор открыт/закрыт, независимый от обычных анкет поток.
- Отправка анкеты в отдельную тему админ-группы (карточка со статусом, без кнопок).
- Взятие анкеты на рассмотрение (только один админ одновременно) переносит всё
  дальнейшее рассмотрение и решение в личные сообщения с ботом — в теме
  остаётся только статус (Свободна / На рассмотрении / Одобрено / Отказано).
- Пока админ рассматривает анкету — работает живой чат-мост: всё, что админ
  пишет боту в личке (кроме команд/кнопок), уходит заявителю, и наоборот.
- Одобрение, отказ с указанием причины, запрос исправления — заявитель может
  подтвердить исправление кнопкой ИЛИ просто прислать исправленное фото/текст
  напрямую в чат с ботом.
- При одобрении обычной анкеты пользователю сразу приходит пригласительная
  ссылка (`APPROVAL_INVITE_LINK` в `.env`).
- Кнопка «У меня спамблок!» — снимает временную антиспам-блокировку сразу же,
  если она помешала прислать исправление.
- При повторной подаче анкеты во время cooldown администрации приходит
  уведомление с кнопками «Сбросить время?» — плюс команда `/resettime ID`
  для владельца, если нужно сбросить кулдаун вручную.
- Чёрный список по ID или `@username` (`/чс`, `/block`, и обратные
  `/разблокировать`, `/unblock`), антиспам с временной блокировкой (админы,
  которые сейчас что-то рассматривают, из-под антиспама исключены), cooldown
  4 дня между подачами обычной анкеты.
- Восстановление состояния после перезапуска (в том числе недозаполненной
  анкеты и незавершённого рассмотрения).

## Заявки на младшего модератора — отдельный поток

1. Владелец добавляет бота в новую (любую) группу, заходит в нужную тему и
   пишет там `/set_admins` — эта тема запоминается как тема для заявок на
   модератора (никак не связана с темой обычных анкет).
2. Там же, в этой теме, владелец пишет `/open_admin` — приём заявок
   открывается, и бот рассылает всем, кто хоть раз писал ему, сообщение
   «Открыт набор на младшего модератора! Напишите /start».
3. На `/start` в личке у пользователя теперь две кнопки: «📝 Подать анкету» и
   «🛡 Подать на пост мл. модератора». Вторая всегда видна, но пока набор не
   открыт — по нажатию просто ответит «Набор недоступен».
4. Чтобы закрыть приём — `/close_admin` в той же теме.
5. Заявки приходят карточками в тему заявок и рассматриваются точно так же,
   как обычные анкеты (взятие → личка админа → решение), включая
   живой чат-мост и исправления.

## Шаг 1. Создать бота через BotFather

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot` и следуйте инструкциям (укажите имя и username бота).

## Шаг 2. Получить токен

BotFather пришлёт токен вида `123456789:AAExampleTokenValue`. Скопируйте его —
он понадобится на шаге 5. **Никому его не передавайте.**

## Шаг 3. Загрузить проект на GitHub

1. Создайте новый репозиторий на [github.com](https://github.com) (можно приватный).
2. Загрузите в него все файлы этого проекта (через сайт GitHub — кнопку
   "Add file → Upload files", либо через `git push`, если умеете пользоваться git).
3. Файл `.env` загружать **не нужно** — он в `.gitignore` и не должен попасть
   в репозиторий, там хранится секретный токен.

## Шаг 4. Подключить GitHub к Railway

1. Зайдите на [railway.app](https://railway.app) и войдите через GitHub.
2. Нажмите "New Project" → "Deploy from GitHub repo" → выберите ваш репозиторий.
3. Railway автоматически найдёт `Dockerfile` и начнёт сборку.

## Шаг 5. Добавить BOT_TOKEN

1. В настройках проекта на Railway откройте вкладку **Variables**.
2. Добавьте переменную `BOT_TOKEN` со значением токена из шага 2.
3. (Необязательно) добавьте остальные переменные из `.env.example`, если хотите
   настроить баннер, GIF, стикеры и т.д. — все они имеют значения по умолчанию.
4. **Важно:** подключите Railway Volume и примонтируйте его в `/app/data`,
   чтобы JSON-файлы с анкетами не терялись при редеплое (Settings → Volumes).

## Шаг 6. Запустить проект

Railway сам перезапустит сервис после сохранения переменных. Проверьте вкладку
**Deployments → Logs** — там должна появиться строка
`Бот запускается. Владелец: 7541580964`.

## Шаг 7. Добавить бота в админскую группу

1. Создайте Telegram-группу для админов (или используйте существующую) с
   включёнными **темами (Topics)**.
2. Добавьте бота в эту группу и выдайте ему права администратора
   (нужно, чтобы он мог писать в темы и закреплять/редактировать сообщения).

## Шаг 8. Зайти в нужную тему

Откройте (или создайте) тему группы, куда должны приходить новые анкеты.

## Шаг 9. Написать /settopic

Владелец бота (Telegram ID `7541580964`) должен написать `/settopic` **внутри
этой темы**. Бот ответит `✅ Эта тема установлена для новых анкет.` — теперь
все новые анкеты будут приходить именно сюда.

## Шаг 10. Проверить подачу тестовой анкеты

1. Напишите боту `/start` от любого аккаунта.
2. Нажмите "📝 Подать анкету" и пройдите все шаги, включая отправку фото.
3. Убедитесь, что карточка анкеты появилась в админ-теме с кнопкой
   "🔎 Взять на рассмотрение".
4. **Важно:** админ, который будет брать анкеты, должен хотя бы раз написать
   боту `/start` в личных сообщениях до этого — иначе бот не сможет открыть
   ему личку при взятии анкеты.
5. Нажмите "🔎 Взять на рассмотрение" — бот откроет админу личку с полной
   карточкой и кнопками, а в теме останется только статус "На рассмотрении".
6. Проверьте полный цикл в личке: одобрить / отказать / запросить исправление
   → пользователь получает уведомление и (если было запрошено исправление)
   может прислать исправленное фото прямо в чат с ботом, без повторного
   заполнения анкеты.
7. Попробуйте написать что-нибудь свободным текстом в личке админа, пока
   анкета на рассмотрении — сообщение должно дойти до заявителя, и наоборот.

## Как получить стикеры (необязательно)

Каждому из 8 вопросов анкеты можно назначить стикер из набора
`https://t.me/addstickers/Akemi_Homura`. Чтобы получить их `file_id`:

1. Локально установите зависимости: `pip install -r requirements.txt`.
2. Создайте файл `.env` на основе `.env.example` и укажите `BOT_TOKEN`.
3. Запустите: `python tools/get_sticker_ids.py`.
4. Скрипт выведет готовую строку `QUESTION_STICKERS=...` — скопируйте её в
   `.env` (локально) или в переменные окружения Railway.

Если оставить `QUESTION_STICKERS` пустым, бот просто не будет отправлять
стикеры к вопросам — на остальную работу это не влияет.

## Про баннер и GIF

- `BANNER_IMAGE` — картинка для `/start`. Можно указать прямую ссылку на
  изображение (например, с imgur) или `file_id`, если картинка уже когда-либо
  отправлялась вашему боту.
- `HELP_GIF` — GIF/видео для раздела помощи, задаётся так же.

## Локальный запуск (для разработки)

```bash
pip install -r requirements.txt
cp .env.example .env
# впишите BOT_TOKEN в .env
python -m bot.main
```

## Запуск через Docker локально

```bash
docker build -t anketa-bot .
docker run --env-file .env -v $(pwd)/data:/app/data anketa-bot
```

## Структура проекта

```
bot/
  main.py            — точка входа, запуск polling
  config.py           — загрузка настроек из переменных окружения
  json_store.py        — атомарное JSON-хранилище (users/anketas/blacklist/settings)
  fsm_storage.py        — файловое хранилище состояний FSM (переживает рестарт)
  questions.py          — список вопросов анкеты
  states.py             — состояния FSM
  texts.py               — тексты сообщений
  keyboards.py            — inline-клавиатуры
  rendering.py             — форматирование карточки анкеты для админов
  card_sync.py                — синхронизация карточки анкеты между темой и личкой
  services/
    users.py               — активная анкета пользователя, cooldown
    anketas.py              — CRUD анкет, атомарные переходы статусов
    blacklist.py             — чёрный список
    settings.py               — админ-тема, счётчик анкет
  middlewares/
    blacklist.py               — блокировка забаненных пользователей
    antispam.py                 — антиспам + защита от двойного клика + force_unblock
  handlers/
    user_start.py                — /start, помощь
    anketa_form.py                — пошаговая анкета, исправление, cooldown-уведомления
    moderation.py                  — /settopic, взятие/решение анкет (в личке)
    owner.py                        — /setanket, /resettime, /чс, /разблокировать
    dm_bridge.py                     — живой чат-мост админ ↔ заявитель
tools/
  get_sticker_ids.py                — получение file_id стикеров
data/                                — JSON-файлы с данными (создаются автоматически)
```

## Ограничения и заметки

- Владелец бота задан фиксированно (Telegram ID `7541580964`), при желании
  можно переопределить через переменную `OWNER_ID`.
- Служебные команды (`/settopic`, `/setanket`, `/resettime`, `/чс`,
  `/разблокировать`) доступны только владельцу.
- Взятие анкеты возможно только если админ уже писал боту `/start` в личке —
  иначе Telegram не позволит боту написать ему первым.
- Хранение данных — только JSON-файлы, без внешних баз данных, поэтому важно
  подключить Railway Volume к папке `/app/data` (см. Шаг 5), иначе данные
  будут теряться при каждом редеплое.
- Кнопки модерации (одобрить/отказать/исправление/освободить) доступны
  только тому администратору, который взял анкету на рассмотрение.
